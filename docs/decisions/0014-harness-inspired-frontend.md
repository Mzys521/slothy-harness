# ADR 0014：参考 DeepSeek Harness 重写前端

状态：已实施。

## 背景

用户要求先清除旧前端，再参照 DeepSeek Harness 重新设计，并严格遵循 docs。
现有工作区的前端与桌面服务已有未提交实现，需要保留其可恢复副本及稳定接口。

## 决策

1. 删除前先在已忽略的 `.slothy/` 备份前端文件并核对哈希；删除范围只限前端源码、入口、配置、公共资源及旧构建。保留依赖缓存与锁文件，再从头编写。
2. 参考上游固定版本的侧栏、居中工作区、圆角输入区和紧凑可展开工具记录；以 Vue 3 实现，保留 Vite/Tailwind 工具链和 pywebview 宿主。上游许可放入前端第三方声明。
3. 按开发指导划分 components、views、stores、services、types、styles。唯一通信边界是受类型约束的 bridge；页面获取 Application DTO，组件展示数据并发出 UI 事件。
4. 品牌常量及语义遵循 Theme-Color-Constraints；绿色用于操作、选中与运行，正文用中性色，奶油色用于温暖表面，棕色限于辅助品牌。支持浅色、深色及系统主题。
5. 运行视图优先展示实际模型/工具/策略事件、重试、结构化任务状态、预算和控制入口。错误节点保留，事件以 cursor 去重，任务切换丢弃过期响应。审批决定不隐式恢复执行。
6. 保留真实项目、灵感、记忆、日志、模式和运行控制。缺失的调度与插件服务显式说明；不扩展模型的文件、Shell、网络或桌面权限，不引入假任务历史。

## 备选方案与理由

整套移植 React/Cordis 插件宿主会更换技术栈并改变通信边界，不符合当前标准。
仅修改旧 App 样式不满足清除后重写的要求。采用独立 Vue 实现，同时保留既有 API。

## 影响与验收

此次变更限于前端、使用文档与浏览器验收脚本。Python 业务接口保持现状。
执行 TypeScript/Vite 构建、现有 Python 单元和集成检查，并以真实本地
HTTP/Application/SQLite 和明确的离线模型替身验证端到端行为与多尺寸截图。
审批、取消与恢复保留宿主既有语义；运行事件缓存仍不等同于持久审计。
