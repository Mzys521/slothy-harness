# ADR 0017：独立工作模式与项目源文件夹

- 状态：已实现
- 日期：2026-10-06
- 关联：[ADR 0016](0016-coding-agent-mode-and-controlled-tools.md)

## 背景

用户要求将 Coding 构造为独立模式，将切换放到左侧顶部，并按提供的参考图展示项目、可折叠的任务列表、创建弹窗与详情菜单。显示名称分别为 `slothy chat` 和 `sloty coding`。源文件夹需要跟随项目，才能同时维护多个项目。

## 决定

1. 内部协议继续使用 `agent_mode=general|coding`，保留现有任务与快照兼容性。唯一模式入口为侧栏顶部菜单。切换清除当前任务投影，分别保留两种模式的草稿和执行预算；已启动的任务继续由原 Runtime 驱动。任务列表和搜索按模式筛选。Chat 隐藏整个项目环境及 Coding 权限表单。
2. 删除旧侧栏、输入框切换及名称弹窗实现，重写 ModeSwitcher、ProjectGroup、ProjectDialog 与组合入口。Coding 项目在侧栏内显示文件夹及子任务，支持独立折叠、置顶、创建任务和编辑。详情展示真实任务数量、路径与可识别的仓库信息。折叠和模式选择是本机 UI 偏好；项目内容与置顶状态由 Application 保存。
3. `ProjectService` 通过注入的目录检查与目录选择函数处理创建、编辑和选择。Infrastructure 使用现有 canonical_root 校验绝对路径、链接、受保护目录和目录身份。Core 保持不变，模型不获得选择器或任意目录配置工具。项目 DTO 不暴露 root_identity。
4. 桌面入口向 ProjectService 注入 pywebview 目录选择器，并在窗口创建后绑定窗口。选择器只允许一个活动调用；取消返回空选择。浏览器宿主明确返回 available=false，界面提供完整路径输入并通过宿主检查后附加，保存时再验证。
5. 新 Coding 任务从所属项目取得 workspace_root 与 root_identity，并结合保存的 Coding 权限创建不可变 coding_binding。修改项目目录只影响新任务，已有任务及待审批任务继续绑定原目录；恢复不重新选目录。目录身份改变时，新任务要求编辑项目重新添加。Settings 保留修改权限、固定检查预设、检查时限和执行预算配置。
6. 为兼容旧接口，纯名称项目仍可读取并补充目录；原 `update_coding_settings.workspace_root` 与无 project_id 的 Coding 创建入口继续兼容。新界面只从项目创建 Coding 任务。权限更新可以省略 workspace_root，保留旧配置的目录和身份，不强制重新检查已经弃用的全局目录。
7. 仓库展示只读取用户配置项目内的普通 `.git/config`，限制大小并拒绝链接；不调用 Git 或网络。仅提取允许的公共托管域名与仓库路径，丢弃认证信息。没有可识别的元数据时省略仓库行，不猜测。Git worktree 的外部 gitdir、私有托管域名和任意远程命令不在本次范围内。

## 验证

离线集成验证项目创建、编辑、置顶与重启保存，拒绝未知字段和跨用户项目，检查目录身份与仓库展示，选择器取消与浏览器回退，多项目目录优先级，以及审批期间改目录后仍写原目录。原生选择器使用窗口替身验证文件夹对话框参数、串行与异常恢复。

浏览器 E2E 使用真实 HTTP/Application/SQLite 和临时源文件夹，外部生成模型为显式测试替身。覆盖顶部模式、独立草稿、项目创建/详情/折叠/置顶/编辑、刷新保存、模式任务与工具隔离、背景任务、真实文件修改和检查审批、完成记忆、主题与窄窗口。模型替身和测试目录不进入生产入口。
