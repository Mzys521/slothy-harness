# ADR 0016：Coding Agent 模式与受控项目工具

- 状态：已实现
- 日期：2026-10-05
- 后续调整：目录改为项目源文件夹，切换改为侧栏独立模式；兼容原 API，见 [ADR 0017](0017-work-modes-and-project-workspaces.md)。

## 背景

桌面 Harness 原先只注册计算和记忆工具。用户要求切换到 Coding Agent，并明确工作目录在设置页另行配置。模式需要改变真实的模型提示、工具目录和运行预算；不能让模型或前端直接指定任意命令、执行器或宿主身份。

## 决定

1. `agent_mode=general|coding` 独立于 `profile=quick|advanced`。缺省仍是通用助手。通用模式保留 5/20 轮与 30/120 秒；Coding 模式采用 20/60 轮与 300/900 秒。Coding 的工具 schema 层至少保留 8192 tokens，总模型窗口与输出预留继续受 ContextConfig 约束。
2. `CodingService` 通过注入的校验器和工厂保存设置、获取工具 DTO 与选择 RuntimeAPI。文件系统和进程操作均在 `infrastructure/coding`；Core 的 Runner、ToolSession、审批和事件契约保持不变。Presentation 仅调用 WorkspaceAPI 白名单。
3. 默认工作目录为空。`update_coding_settings` 接受项目绝对路径、是否允许申请修改、固定检查允许列表与 1–120 秒单次检查时限。设置按宿主用户保存到 WorkspaceCatalog。新任务检查目录是否仍存在及身份是否一致，并将整个配置绑定到任务目录；更新设置不扩大已有任务权限。重启按任务原绑定创建执行器，再登记快照，查询不执行工具。
4. 注册 `list_files`、`read_file`、`search_code`（IDEMPOTENT），以及按配置注册的 `edit_file`、`write_file`、`run_checks`（UNVERIFIABLE）。后者第一次执行也通过 ToolJournal 请求单次人工批准；批准与恢复分开。执行器还核对宿主 approval_id。ContextToolExecutor 在普通工具上委托底层校验，使非法路径和检查在申请批准之前返回错误。
5. 文件路径只能相对于绑定目录；绝对路径、父目录跳转、Windows ADS、保留名称、符号链接、junction/reparse point、硬链接和常见密钥目录/文件被拒绝。枚举与检索跳过依赖、构建和运行数据目录；UTF-8 文件至多 1 MiB，目录扫描、搜索文件数、总字节数和结果数量有上限。`.env.example` 可读取，实际 `.env` 与私钥不可读取。长结果复用现有 get_result 分页和外化机制。
6. 修改使用完整文件 SHA256 与唯一原文匹配；覆盖已有文件必须提交 read_file 的指纹。执行前和提交前检查变化，保留已有 BOM 与文件权限，临时文件完成后原子替换；新文件以排他创建提交。没有删除工具。
7. 项目检查只有 `python_unit`、`python_integration`、`npm_build`、`npm_test`、`git_diff` 五个预设。宿主选择固定参数、固定目录和可用解释器，`shell=False`，npm 通过 node 与 npm-cli.js 启动。移除子进程环境中的提供方密钥及任意 Python/Node 注入变量；输出最多 64 KiB，返回真实退出码、超时、截断和耗时。进度事件只有固定阶段和计数。

## 实际保证与限制

路径检查和批准是文件能力边界，并非操作系统沙箱。获批的项目测试、构建脚本拥有当前用户的系统权限；固定预设不会把项目代码变成可信代码。同步取消依然在 Runtime 边界生效，运行中的检查依靠其自身超时；超时在 Windows 尝试终止所创建 PID 的进程树，在 POSIX 终止进程组，不承诺停止已脱离该树的后台进程。路径和指纹检查可阻止已观测到的变化，但不承诺在恶意并发目录替换下消除所有文件系统竞争窗口。

尚无任意终端、自动安装、Git 提交/推送、删除文件、网络抓取或永久授权。目录被替换后新任务要求重新保存设置；历史任务仍保持原身份，不自动改绑。所有模式继续仅在完成快照提交后保存历史记忆。

## 验收

临时文件系统和本地测试子进程验证路径、密钥、链接、指纹、唯一替换、批准、只读设置、真实退出码、超时和输出上限。桌面集成使用离线模型验证模式目录隔离、完成记忆门槛、两次独立审批、拒绝、审批期间文件变化，以及更新设置后重启恢复仍写原目录。浏览器 E2E 从空目录设置开始，验证保存、模式切换、真实文件修改、检查审批、刷新保存及窄屏布局。生产组装不包含测试模型或临时目录。
