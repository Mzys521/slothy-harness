# ADR 0015：完成任务后写入历史记忆

- 状态：已采纳
- 日期：2026-10-05
- 关联：ADR 0012、0013

## 问题

桌面为每次输入创建独立 Run。此前仅有手工 MemoryAPI 写入，没有完成任务的自动历史记录；模型面对“我刚刚问了什么”时缺少上一轮证据，可能把 current_user_input 或 task_state.goal 当成历史提问。仅有工具结果的 observation 不等于已完成对话，也不能据此推断用户历史。

## 决定

1. 由 Application 的 RuntimeService 注入可选 MemoryService。只在 `run` / `resume` 正常返回 `COMPLETED` 且完成快照已提交后，保存原始用户输入与最终回答。不能在 RunCompleted 监听器中写入，因为事件早于完成快照的提交；创建、进行中、暂停、待审批、失败和取消均不写自动历史。
2. MemoryService 以宿主身份、执行标识、完成时间、消息角色和字符范围构造有来源的分段。SQLite 在同一事务中提交全部输入/回答及关键词索引，避免部分写入。确定性标识保证同一完成结果不产生重复记录；embedding 故障仍提交关键词记录。模型没有写历史的工具，手工 API 不能占用 `completed_run` 来源或 `run:` 标识。
3. 创建新 Run 时，宿主只读取同一用户最近已完成任务的首段输入，注入不可信 long_term_memory。读取不调用模型、embedding 或远程检索。较早/完整片段仍可通过 search_memory 获取；这不是跨 Run 的完整消息会话。
4. 当前输入独立留在 current_user_input，TaskState.goal 仍是当前目标。提示规则明确：询问“上一轮/刚刚”依据已完成历史，没有证据则说明缺失，不能重复当前问题来替代历史。首段历史来源在本次 Run 中保留，后续空检索或检索失败不会擦掉上一轮提问；它仍受既有预算裁剪约束，不成为 system 指令。
5. LayeredContext 快照 version 2 增加 `recent_memory_ids`，保存宿主为本次 Run 注入的历史来源标识。version 1 恢复时只补空集合；不把旧活动消息转换成已完成历史，不重新执行工具。恢复完成后以快照中的宿主目标保存原输入。
6. Runtime 和记忆是两个事务域。记忆提交失败返回稳定的 `memory_error`，保留已完成状态、结果及快照，不能声称写入成功或将其改成执行失败。查询、加载已完成快照和服务重启均不重写记录，不自动补造之前未保存的对话。

## 备选方案

- 创建任务时把输入写入长期记忆：尚未完成的当前问题会污染历史检索，拒绝采用。
- 订阅 RunCompleted 立即保存：最终快照可能随后提交失败，无法满足完成持久化边界，拒绝采用。
- 仅修改模型提示：没有上一轮真实记录时不能恢复历史事实，需要实际的完成后存储与加载。

## 后果与验证

Core 只扩展存储协议和上下文数据来源，数据库与 SDK 仍在 Infrastructure，生命周期协调留在 Application。默认 RuntimeService 不注入记忆时保持原行为；桌面 quick/advanced 共用同一用户的完成历史。

历史从本次修复后成功完成的任务开始保存；先前缺失的对话不会被模型推测或补造。长记录按字符范围完整保存，但默认只注入最近任务的首段输入；检索与预算限制仍存在。故障后不自动重跑已完成任务来补写记忆。

测试使用假模型、假 embedding 和临时 SQLite，覆盖当前输入不可提前检索、跨模式追问、空检索/失败保留历史、旧快照兼容、暂停及审批后恢复、取消/失败不写、完成快照失败不写、记忆错误保留最终结果、分段无丢失、整批事务回滚与用户归属过滤。
